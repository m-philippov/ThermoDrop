# ThermoDrop

Настольное приложение (Python + Qt) для анализа температурных полей висящей капли
по кадрам тепловизора. Работает на Windows 7 SP1 / 10 / 11.

## Возможности

| Окно | Что делает |
|---|---|
| **1. Температурное поле** | Кадр целиком, эллипс выделения (перемещение, размер и поворот мышью или точными значениями), автопоиск капли, поворот/транспонирование кадра, режим T или ΔT = T − Tоп |
| **2. Трёхмерная диаграмма** | Столбчатая 3D-диаграмма области в стиле MATLAB `bar3`. Мышь: ЛКМ — вращение, СКМ — сдвиг, колесо — масштаб, Ctrl+колесо / Shift+колесо — верх / низ шкалы, Alt+колесо — высота столбцов. Экспорт PNG/JPG/TIFF/SVG/PDF с заданным размером и dpi |
| **3. Гистограмма** | Распределение температур в эллипсе или по всему кадру: все значения, выше или ниже порога. Порог задаётся перетаскиванием линии (вертикальной или, при «T по вертикали», горизонтальной). Экспорт изображения и CSV |
| **Журнал** | Все действия пользователя и события приложения. Дублируется в файл `%LOCALAPPDATA%\ThermoDrop\logs\thermodrop.log` (ротация 5×5 МБ) |

Ещё есть экспорт области в CSV (матрица или список точек) и открытие файла перетаскиванием в окно.

### Формат входных файлов

Текстовые таблицы `*.csv`, `*.txt`, `*.dat`, `*.tsv`. Первая строка — необязательный заголовок
`строк;столбцов`. Разделитель (`;`, Tab, пробелы, `,`) и десятичный знак (запятая или точка)
определяются автоматически. Кодировка: UTF-8 или CP1251. Бинарные `*.gtsi`/`*.SIT` не поддерживаются:
их нужно экспортировать в CSV из ПО тепловизора.

## Архитектура

```
thermodrop/
├── core/              Доменный слой: чистый Python + NumPy, без Qt
│   ├── models.py        ThermalField, EllipseRegion, RegionData, HistogramResult, перечисления
│   ├── geometry.py      маска и ограничивающий прямоугольник эллипса
│   ├── reference.py     стратегии опорной температуры + фабрика
│   ├── analysis.py      вырезка области, гистограмма, укрупнение сетки
│   └── detection.py     автопоиск капли (порог, морфология, моменты)
├── fileio/            Инфраструктура ввода-вывода
│   ├── readers.py       интерфейс FieldReader, DelimitedTextReader, ReaderRegistry
│   └── exporters.py     экспорт CSV
├── rendering/         Отрисовка на matplotlib.Figure (без Qt-виджетов)
│   ├── bar3d.py         Bar3DRenderer + неизменяемый Bar3DStyle
│   ├── histogram.py     HistogramRenderer + HistogramStyle
│   └── colormaps.py
├── services/          Прикладной слой
│   ├── session.py       AnalysisSession: единый источник состояния, сигналы Qt
│   └── export_service.py сценарии экспорта
├── infrastructure/    Журналирование (файл + окно, перехват исключений и сообщений Qt), пути
├── ui/                Представление (PyQt5)
│   ├── main_window.py   компоновка, меню, экспорт, drag&drop, сохранение настроек
│   ├── roi_adapter.py   ROI pyqtgraph ↔ EllipseRegion
│   ├── dialogs/
│   └── widgets/         field_view, bar3d_view, histogram_view, log_view, common
└── app.py             Composition root: создание и связывание объектов
```

Зависимости направлены строго внутрь: `ui → services → rendering/fileio → core`.
Доменный слой ничего не знает о Qt, поэтому покрыт модульными тестами без GUI.

Где какие паттерны:

* **Наблюдатель.** `AnalysisSession` публикует сигналы `field_changed`, `region_changed`,
  `region_data_changed`, `histogram_changed`. Окна подписываются на них и не связаны друг с другом напрямую.
* **Стратегия.** Способ вычисления опорной температуры (`ReferenceStrategy`), рендереры, читатели файлов.
* **Фабрика / реестр.** `make_reference_strategy`, `ReaderRegistry`. Новый формат файла — это новый `FieldReader`, остальной код менять не нужно (OCP).
* **Внедрение зависимостей.** Все объекты создаются в `app.py` и передаются через конструкторы.
* **Объект-значение.** Неизменяемые `EllipseRegion`, `Bar3DStyle`, `HistogramStyle` (`dataclass(frozen=True)`).
* **Адаптер.** `roi_adapter` переводит геометрию pyqtgraph в доменную модель.
* Один рендерер рисует и на экране, и при экспорте, поэтому сохранённая картинка совпадает с тем, что видно в окне.

## Запуск из исходников

```bat
py -3.8 -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python main.py ["путь\к\файлу.csv"]
python -m pytest
```

Код совместим с Python 3.8–3.14.

## Руководство пользователя

Готовый PDF лежит в [doc/Руководство ThermoDrop.pdf](doc/). Источник — `thermodrop/resources/guide/guide.html`
со скриншотами из `thermodrop/resources/guide/img/`. Тот же HTML открывается внутри программы
(«Справка → Руководство пользователя», F1), поэтому руководство доступно и без программы просмотра PDF.
Пересобрать PDF: `python packaging/make_guide.py [--preview папка]`. При сборке дистрибутива PDF пересобирается
автоматически, кладётся в `doc` рядом с программой и получает ярлык в меню «Пуск».

## Сборка дистрибутива (Windows 7/10/11)

```bat
packaging\build.bat [путь\к\python3.8.exe]
```

Скрипт создаёт `.venv38`, ставит зафиксированные зависимости, прогоняет тесты и собирает
`dist\ThermoDrop\ThermoDrop.exe` через PyInstaller. Если установлен Inno Setup 6, он также собирает
установщик `packaging\Output\ThermoDrop-1.0.0-setup.exe`.

Почему именно такие версии:

* **Python 3.8** — последняя версия Python, которая работает на Windows 7.
* **Qt 5.15 (PyQt5)** работает на Windows 7, а Qt 6 — только на Windows 10 и новее.
* Разрядность программы совпадает с разрядностью Python, на котором она собрана. Для 32-битной Windows 7 соберите программу 32-битным Python 3.8.
* На Windows 7 нужен SP1 и Universal C Runtime (обновление KB2999226). Если на машине их нет, положите
  `vc_redist.x64.exe` (или `x86`) версии VC++ 2015–2019 в папку `packaging\`, и установщик поставит его сам.
